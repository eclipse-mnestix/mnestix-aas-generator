# Contributing to Mnestix AAS Generator

Thanks for your interest in contributing to Mnestix! We are building a community around Mnestix and welcome contributions of all kinds — bug reports, feature requests, documentation, and code. Issues that are particularly suitable for a first contribution are labeled [`good first issue`](https://github.com/eclipse-mnestix/mnestix-aas-generator/labels/good%20first%20issue).

If this is your first time contributing to an Eclipse project, we recommend reading the general guide: [Contributing to an Eclipse project](https://www.eclipse.org/contribute/).

## Eclipse Foundation Terms of Use

By contributing to this project, you agree to the Eclipse Foundation's [Terms of Use](https://www.eclipse.org/legal/termsofuse.php).

## Eclipse Contributor Agreement (ECA)

All contributors must sign the [Eclipse Contributor Agreement (ECA)](https://www.eclipse.org/legal/eca/) to ensure that the necessary intellectual property (IP) rights to the contribution are granted. You can sign the ECA here: **[accounts.eclipse.org/user/eca](https://accounts.eclipse.org/user/eca)**.

Every commit must include a `Signed-off-by` line, using the same email address associated with your Eclipse Foundation account:

```bash
git commit -s -m "Your commit message"
```

A GitHub check ("ECA hook") verifies that all commits in a pull request come from contributors with a valid ECA on file.

## Source Code Repository

The canonical repository for this project is [github.com/eclipse-mnestix/mnestix-aas-generator](https://github.com/eclipse-mnestix/mnestix-aas-generator). All contributions are made and reviewed here via pull requests.

## How to Contribute

1. Check the [issue tracker](https://github.com/eclipse-mnestix/mnestix-aas-generator/issues) for open issues, or open a new one to discuss your idea/bug before starting significant work.
2. Fork the repository and create a branch for your change.
3. Make your changes, following the existing code style and adding tests where applicable.
4. Commit with `git commit -s` (see [ECA](#eclipse-contributor-agreement-eca) above).
5. Open a pull request against the `dev` branch. A maintainer will review it, confirm ECA coverage, and merge it once approved and CI passes.

## Communication

Questions, ideas, or feedback? Reach us at [mnestix@xitaso.com](mailto:mnestix@xitaso.com) or through the [Mnestix website](https://xitaso.com/kompetenzen/mnestix/#support).
